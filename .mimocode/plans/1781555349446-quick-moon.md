## 一、数据库层 (database.rs)

### 1.1 核心表

**source_data** — 统一源数据，所有业务实体的清洗全文
- `id INTEGER PK`, `source_type TEXT`, `source_id TEXT`, `title`, `content`, `created_at`, `updated_at`
- `UNIQUE(source_type, source_id)` — 一个实体一条记录
- 写入方式：SQL 触发器（notes/products/projects/todos INSERT/UPDATE 时 UPSERT），文件通过 `file_sync_to_source_data()` 写入

**knowledge_chunks** — 双层知识块
- `id INTEGER PK`, `chunk_id TEXT`, `chunk_type TEXT` ('parent'|'child'), `parent_id TEXT` (child→parent), `source_data_id INTEGER` (parent→source_data), `content`, `doc_title`, `chunk_index INTEGER`, `content_hash TEXT`, `base_weight REAL DEFAULT 1.0`, `last_access_at INTEGER`, `access_count INTEGER`
- INDEX: `idx_kc_parent(parent_id)`, `idx_kc_source(source_data_id)`, `idx_kc_type(chunk_type)`

**vector_cache** — 向量标记
- `chunk_id INTEGER PK` (= knowledge_chunks.id)

**LanceDB knowledge_vectors** — 向量存储
- `rowid(Int64)`, `vector(FP32[1024])`, `parent_id`, `doc_id`, `content_hash`, `tags`

**FTS5**:
- `kk_chunks_fts(doc_title, content, tokenize='unicode61')` — child 块全文检索
- `global_search_fts(source_type UNINDEXED, source_id UNINDEXED, title, content, content='source_data', content_rowid='rowid')` — source_data 全局检索

**实体图谱**:
- `entities(id PK, name, type, aliases, description, metadata, confidence, UNIQUE(name,type))`
- `entity_mentions(id PK, entity_id FK→entities, chunk_id, source_type, source_id, position, context, confidence, UNIQUE(entity_id,chunk_id))`

**管线队列**:
- `ai_sync_queue(id PK, source_table, source_id, is_embedded(0=pending,1=done,-1=failed), retry_count, last_dedup_key, last_error, UNIQUE(source_table,source_id))`
- `ai_tag_queue(id PK, source_type, source_id, status(0=pending,1=done), tag_type='ai_shadow', retry_count, last_error, UNIQUE(source_type,source_id))`

### 1.2 触发器链

```
INSERT/UPDATE notes → sd_notes_insert/update → UPSERT source_data
DELETE notes → sd_notes_delete → DELETE source_data
DELETE source_data → sd_chunks_delete → DELETE knowledge_chunks
DELETE source_data → sd_fts_delete → DELETE global_search_fts
INSERT knowledge_chunks (child) → kk_chunks_fts_insert → INSERT kk_chunks_fts
DELETE knowledge_chunks (child) → kk_chunks_fts_delete → DELETE kk_chunks_fts
```

产品/项目/待办/动态 各有对应的 INSERT/UPDATE/DELETE 触发器。

### 1.3 统一删除函数

`cleanup_kb(source_type, source_id)` (file_commands.rs:9-37):
1. 查 source_data.id
2. 收集 chunk_ids = SELECT id FROM knowledge_chunks WHERE source_data_id=?
3. DELETE source_data → 触发器自动删 knowledge_chunks + global_search_fts
4. DELETE vector_cache WHERE chunk_id IN (...)
5. LanceDB::delete_chunks_by_rowids(chunk_ids)

## 二、数据采集流程

### 2.1 文件入库 (file_commands.rs)

`upload_file_core()` (L182):
1. `compute_file_hash()` — 流式 SHA-256
2. CAS 去重：`find_existing_by_hash(hash)` — 复用已有 file_assets
3. 物理存储：`flat_disk_path(hash)` → copy
4. 创建 `file_assets(id, file_ext, file_size, content_hash, parse_status='PENDING')`
5. 创建 `file_relations(id, file_id, entity_type, entity_id, custom_name)`
6. 触发 `ai_tag::enqueue_tag_task()`

### 2.2 文件解析 (file_parser.rs)

`parse_file_smart(path, ext)` — 格式路由：
- PDF: `try_pdfium_render()` + OCR 优先，`pdf-extract` 兜底
- 图片: `try_ocr_image()` → base64 → vision API
- DOCX: `read_docx_to_markdown()` — XML 解析
- XLSX: `read_xlsx()` — calamine → `clean_xlsx()`
- PPTX: `read_pptx()` — XML slide 提取
- TXT/MD/CSV/JSON: 直接读取

`clean_extracted_text_with_hint(raw, ext)`:
- `merge_pdf_broken_lines()` — PDF 换行合并
- `strip_garbled_lines()` — 乱码行过滤
- `strip_page_numbers()` — 页码过滤
- `ensure_table_separator()` — 表格分隔线补全

### 2.3 源数据同步 (source_doc_sync.rs)

`sync_entity_to_source_docs(source_type, source_id, title, content)`:
1. `sanitize_chars(content)` — 清洗
2. `INSERT OR REPLACE INTO source_data`
3. `scheduler.enqueue(source_type, source_id)` — 触发防抖物化
4. `ai_tag::enqueue_tag_task()` — 入队标签任务

### 2.4 智能分块 (smart_chunker.rs)

常量: `COMPACT_THRESHOLD=350`, `MAX_PARENT=1800`, `FOCUSED_TARGET=350`

`parse_blocks(text)` — 逐行解析：
- `#` 开头 → Heading(level=1-6)
- ` ``` ` → Code
- `<table>` 或 `|` → Table
- `>` → Quote
- `-`/`*`/`+`/`1.` → List
- `---`/`***` → HorizontalRule
- 空行 → Empty
- 其他 → Paragraph

`build_sections(blocks)` — 标题层级栈：
- 标题触发新 Section
- 非标题追加到当前 Section

`accumulate_adaptive_parents(sections)` — 累积 parent 块：
- 遍历 sections，累积 blocks 到 parent
- 表格 → `semantic_builder::html_table_to_kv()` 转 KV 格式
- 遇标题且已累积 >COMPACT_THRESHOLD → 切割
- 超过 MAX_PARENT → 强制切割
- `merge_short_tails()` 合并过短的尾块

`split_into_focused(prefix, text, target)` — child 块：
- 按行切分，每块 target 字符
- 带 prefix 上下文

## 三、知识管线 (knowledge_pipeline.rs)

### 3.1 启动流程

```
start() → 8 步:
1. purge_stale_queue_entries() — 清理僵尸队列
2. 种子同步队列 (cold_start_seed_sync_queue / seed_from_source_data)
3. reset_retryable_failures() — is_embedded=-1 AND retry_count<3 → 重置
4. clean_vector_cache() — orphan 清理
5. auto_clean_trash() — notes deleted >30天
6. WAL checkpoint
7. 启动 DebouncedMaterializer (4 worker)
8. 启动 scheduler_loop (tokio thread)
```

### 3.2 调度器循环

`scheduler_loop()`:
- 许可证检查
- 每 ~2min: `seed_new_records()` — 从 source_data 补种 ai_sync_queue
- 每 ~30s: `seed_from_source_data()`
- 每 tick: 处理 5 个 `process_sync_task()` + 5 个 `vectorize_new_chunks(5)`
- 自适应 sleep: 有任务 50ms，无任务 5000ms

### 3.3 防抖物化 (debounced_sync.rs)

`DebouncedMaterializer`:
- `enqueue(source_type, source_id)` — Pending(now+5s)
- `worker_loop` — 扫描过期 Pending → Processing → `process_single_entity()` (4 并发 Semaphore)
- 5 秒防抖窗口避免频繁重建

### 3.4 同步任务处理 (ai_sync.rs)

`process_sync_task()`:
1. 从 ai_sync_queue 取 is_embedded=0 的任务
2. `materialize_task()` — 读 source_data，获取内容
3. `import_sync_document()`:
   - smart_chunker 分块
   - 比较 content_hash 跳过未变化内容
   - 删除旧 chunks + vector_cache + LanceDB vectors
   - 插入 parent rows
   - 每 parent: ≤350字符 → 1 compact child; 否则 → `split_text_by_lines(text, 350)` focused children
   - base_weight=5.0
4. 标记 is_embedded=1
5. 入队 ai_tag_task

## 四、向量化 (hybrid_knowledge.rs + embedding_client.rs)

`vectorize_new_chunks(batch_size)`:
1. SELECT child chunks NOT IN vector_cache
2. 截断 content 到 150 字符
3. `embed_texts_with_caller()` → OpenAI-compatible /v1/embeddings
4. `lancedb_client::insert_vectors_full()` → LanceDB
5. INSERT vector_cache

`EmbeddingConfig`: base_url, api_key, model, dimensions(1024), timeout_secs(30)
- 从 system_config.ai_config.embedding 读取
- 30 秒缓存
- 支持 AES-256-GCM 加密 API Key

## 五、Agent 工作流 (agent_workflow.rs)

### 5.1 入口

`agent_chat_workflow(user_query, max_iterations, history, app_handle)`:
- max_iters: 默认 8，clamp(2, 20)
- 构建 tools 定义 + SystemPrompt + 恢复历史消息
- 重建 SessionMemory 从历史

### 5.2 工具定义

```json
ext_tool_search: { keywords: string[], filter_tags?: string[] }
ext_tool_object: { query: string }
ext_tool_traverse: { chunk_id: string, edge_type: "next"|"prev"|"related"|"references", target_name?: string, radius?: int }
ext_tool_act: { action: "create_todo"|"update_todo_status"|"update_project_status", ... }
```

### 5.3 搜索流程

`execute_search_knowledge(keywords, filter_tags, scope_rowids, visited_sources)`:

1. **横向检索**: 关键词 LIKE → projects/products/files/notes → 匹配对象信息
2. **向量检索**: query → embedding → LanceDB search_vectors_with_parent (top 30)
3. **FTS5 检索**: 关键词 OR 组合 → fts5_search_chunks (top 30)
4. **可选过滤**: filter_tags → get_child_rowids_by_tag_names → 过滤
5. **RRF 融合**: `rrf_fusion(fts_rowids, vec_rowids, k=60.0)`
6. **结果构建**: 每个命中 → 查 parent chunk + source_data → 构建元数据 (source_type, source_id, ChunkID, 漫游提示)
7. **去重**: 按 source 去重 (每个 source 只取第一个)
8. **Workspace 更新**: 父块被采纳 → `activate_child_chunks()` → synapse
9. **横向反哺**: `execute_horizontal_search()` → 标签/实体匹配对象

### 5.4 对象查询

`execute_object_get(query)`:
- LIKE 搜索 products/projects/files/notes/todos
- 返回结构化属性面板

### 5.5 图谱漫游

`execute_traverse(chunk_id, edge_type, radius, visited, target_name, counter)`:
- **Next/Prev**: 按 chunk_index 翻页，连续遍历 >5 次警告
- **Related**: 同产品/同项目的其他块
- **References**: 实体引用的关联块
- 边界阻断信号：到达文档首尾时明确提示 LLM

### 5.6 ReAct 循环

```
loop {
  iters += 1
  LLM(messages, tools) → choice
  if no tool_calls → return final answer
  if tool_calls:
    if iters >= max_iters → force summarize
    执行每个 tool_call → result
    dedup_cache 防重复调用
    SessionMemory.update_from_line(result)
    
    断路器检查:
    ① 迭代>=4 且连续两轮 result<50字符 → 停止
    ② Search 关键词 Jaccard > 0.6 → 停止
    ③ Search 无新 ChunkID → 停止
    
    注入 scratchpad 到 system prompt
}
```

### 5.7 会话记忆

`SessionMemory`:
- `active_objects: Vec<ActiveObject>` — LRU max 20
- `visited_chunks: HashSet<String>` — 已访问 chunk_id
- `visited_sources: HashSet<String>` — 已访问 source
- `focus: Focus` — entities, intent, open_questions
- `observations: Vec<String>` — 观察记录
- `hypotheses: Vec<String>` — 假设
- `search_keywords: Vec<Vec<String>>` — 搜索历史

`generate_scratchpad()` → 500字符上限:
- Current Goal
- Active Objects (带 tag queries + focus 标记)
- Unknown (open questions)
- Collected Evidence
- Evidence Path

## 七、设计亮点与风险

### 亮点
1. 双层块：parent 保持上下文，child 精确检索
2. 混合检索：FTS5 + LanceDB + RRF 融合
3. 突触演化：base_weight 动态调整
4. Agent 工具化：ReAct + 4 工具 + 断路器
5. 防抖物化：5 秒窗口避免频繁重建
6. 统一删除：cleanup_kb 完整清理所有层

### 风险
1. `vector_cache` 清理依赖显式调用，触发器链不覆盖
2. `reranker_client` 是 stub，无重排序能力
3. `ext_tool_find_related_knowledge` 是 stub
4. 会话记忆无上限 (visited_chunks/visited_sources 只增不减)
5. 向量维度硬编码 1024（已修复为懒建表）
