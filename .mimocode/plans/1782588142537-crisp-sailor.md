## 架构目标

```
Phase 1A（并行 tool_calls）:
User → LLM → [search(A), search(B), traverse(C)] 并行执行 → LLM → answer
       └── 1 轮 ──┘   └── 1 轮（3 工具并行）──┘                    └── 1 轮 ──┘

Phase 1B（Planner）:
User → LLM(Planner) → TaskPlan → DAG → 并行执行 → LLM → answer
       └── 1 轮 ──┘        └── 1 轮 ──┘          └── 1 轮 ──┘
```

## Phase 1A：并行 tool_calls

### 目标
当 LLM 在同一轮返回多个 tool_calls 时，并行执行它们。改动最小，收益最大。

### 核心问题
当前 `for tc in &atc { ... }` 串行执行所有工具调用。主要障碍：
- `session` 需要 `&mut`，Rust 不允许多个 `&mut` 引用
- 工具执行和 SessionMemory 更新交织在一起
- `traverse_source_counter` 是可变状态

### 设计：执行与更新分离

**Step 1：定义 `SessionEffect` 枚举**
```rust
// agent_workflow.rs 新增
enum SessionEffect {
    RecordSearch(Vec<String>),
    MarkSourceVisited(String),
    UpdateObject { obj_type: String, obj_id: String, name: String },
    MarkChunkVisited(String),
}
```

**Step 2：提取工具执行为纯函数**
将 `match tc.function.name` 的每个分支提取为独立的 async/sync 函数，返回 `(String, Vec<SessionEffect>)`：
- `execute_tool_search(args) -> (String, Vec<SessionEffect>)`
- `execute_tool_object(args) -> (String, Vec<SessionEffect>)`
- `execute_tool_traverse(args, traverse_source_counter) -> (String, Vec<SessionEffect>)`
- `execute_tool_act(args) -> (String, Vec<SessionEffect>)`
- `execute_tool_batch_search(args) -> (String, Vec<SessionEffect>)`
- `execute_tool_manage_policy(args) -> (String, Vec<SessionEffect>)`

**Step 3：并行执行 + 顺序更新**

```rust
// 1. 预去重（顺序）
let mut to_execute: Vec<(usize, &ToolCall)> = Vec::new();
let mut cached_results: HashMap<usize, String> = HashMap::new();
for (i, tc) in atc.iter().enumerate() {
    let key = (tc.function.name.clone(), tc.function.arguments.clone());
    if let Some(cached) = dedup_cache.get(&key) {
        cached_results.insert(i, cached.clone());
    } else {
        to_execute.push((i, tc));
    }
}

// 2. 并行执行（async 工具用 join_all，sync 工具串行）
let mut results: Vec<(usize, String, Vec<SessionEffect>)> = Vec::new();
for (_, cached_res) in &cached_results {
    // 直接使用缓存结果
}

// 分离 async 和 sync 工具
let mut async_handles = Vec::new();
let mut sync_results = Vec::new();
for (i, tc) in &to_execute {
    match tc.function.name.as_str() {
        "ext_tool_search" | "ext_tool_search_knowledge_base" | "ext_tool_batch_search" => {
            // async：spawn 并行任务
            async_handles.push(tokio::spawn(execute_tool_async(tc.clone())));
        }
        _ => {
            // sync：顺序执行
            sync_results.push(execute_tool_sync(tc, &mut traverse_source_counter));
        }
    }
}
// 等待所有 async 任务完成
for handle in async_handles {
    let (i, result, effects) = handle.await??;
    results.push((i, result, effects));
}

// 3. 顺序应用 SessionEffects（合并到 session）
for (i, result, effects) in &results {
    for effect in effects {
        match effect {
            SessionEffect::RecordSearch(kw) => session.record_search(&kw),
            SessionEffect::MarkSourceVisited(s) => session.mark_source_visited(s),
            // ...
        }
    }
    dedup_cache.insert(key, result.clone());
    round_tools.push(...);
    messages.push(ChatMessage { role: Tool, content: Some(result), ... });
}
```

### 关键文件改动

| 文件 | 改动 | 说明 |
|------|------|------|
| `agent_workflow.rs` | 新增 `SessionEffect` 枚举 | 定义会话效果类型 |
| `agent_workflow.rs` | 提取 `execute_tool_*` 函数 | 每个工具的纯执行逻辑 |
| `agent_workflow.rs` | 重写 `for tc in &atc` 循环 | 并行执行 + 顺序更新 |

### 约束
- `ext_tool_traverse` 需要 `&mut traverse_source_counter`，只能串行或预 clone
- `ext_tool_manage_policy` 做 DB 写入，应串行执行
- 工具结果追加到 `messages` 的顺序不影响 OpenAI API（通过 `tool_call_id` 关联）

## Phase 1B：Planner 集成

### 目标
在 ReAct 循环前插入 Planner 层，LLM 输出结构化 TaskPlan，编译为 DAG，并行执行。

### 新增数据结构

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
struct TaskPlan {
    goal: String,
    requirements: Vec<Requirement>,
    reasoning: Option<String>,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
struct Requirement {
    #[serde(rename = "type")]
    req_type: String,  // "OBJECT" | "SEARCH" | "TRAVERSE" | "ACT"
    target: Option<String>,
    keywords: Option<Vec<String>>,
    chunk_id: Option<String>,
    edge_type: Option<String>,
    action: Option<String>,
    params: Option<Value>,  // ACT 的额外参数
    depends_on: Option<usize>,  // 依赖的 requirement index
}
```

### Planner Prompt

```
你是一个认知规划器。分析用户需求，输出信息获取计划。

## 输出格式（JSON，不要输出其他内容）

{
    "goal": "用户意图的一句话描述",
    "requirements": [
        {
            "type": "SEARCH",
            "keywords": ["关键词1", "关键词2"],
            "depends_on": null
        },
        {
            "type": "OBJECT",
            "target": "对象名称",
            "depends_on": null
        },
        {
            "type": "TRAVERSE",
            "chunk_id": "来自 SEARCH 结果的 ChunkID",
            "edge_type": "next",
            "depends_on": 0
        },
        {
            "type": "ACT",
            "action": "create_todo",
            "params": {"title": "...", "content": "..."},
            "depends_on": null
        }
    ],
    "reasoning": "你的推理过程"
}

## 规则
1. 只输出 JSON
2. requirements 可以并行执行（depends_on 为 null 的可以并行）
3. TRAVERSE 必须有 depends_on（指向提供 chunk_id 的 SEARCH）
4. ACT 的 depends_on 通常为 null（独立执行）
5. 简单问题（问候、闲聊）requirements 为空数组
```

### JSON 提取容错

```rust
fn extract_json_plan(text: &str) -> Option<TaskPlan> {
    // 1. 尝试直接解析
    if let Ok(plan) = serde_json::from_str::<TaskPlan>(text) {
        return Some(plan);
    }
    // 2. 从 ```json ... ``` 中提取
    if let Some(start) = text.find("```json") {
        let json_start = start + 7;
        if let Some(end) = text[json_start..].find("```") {
            if let Ok(plan) = serde_json::from_str::<TaskPlan>(&text[json_start..json_start+end].trim()) {
                return Some(plan);
            }
        }
    }
    // 3. 从 { ... } 中提取
    if let Some(start) = text.find('{') {
        if let Some(end) = text.rfind('}') {
            if end > start {
                if let Ok(plan) = serde_json::from_str::<TaskPlan>(&text[start..=end]) {
                    return Some(plan);
                }
            }
        }
    }
    None
}
```

### DAG 编译 + 并行执行

```rust
async fn execute_plan(
    plan: &TaskPlan,
    session: &SessionMemory,
    traverse_source_counter: &mut HashMap<String, usize>,
) -> Vec<(String, Vec<SessionEffect>)> {
    let mut results: Vec<Option<(String, Vec<SessionEffect>)>> = vec![None; plan.requirements.len()];
    let mut executed = HashSet::new();

    loop {
        // 找出所有 dependencies 已满足的 pending tasks
        let ready: Vec<usize> = plan.requirements.iter().enumerate()
            .filter(|(i, req)| !executed.contains(i)
                && req.depends_on.map_or(true, |d| executed.contains(&d)))
            .map(|(i, _)| i)
            .collect();

        if ready.is_empty() { break; }

        // 并行执行这一层
        let mut handles = Vec::new();
        let mut sync_tasks = Vec::new();

        for idx in &ready {
            let req = &plan.requirements[*idx];
            match req.req_type.as_str() {
                "SEARCH" | "OBJECT" | "TRAVERSE" => {
                    // 需要 async 的工具
                    handles.push(tokio::spawn(execute_requirement(req.clone(), session.snapshot())));
                }
                "ACT" => {
                    // ACT 串行执行
                    sync_tasks.push(execute_requirement_sync(req, session));
                }
                _ => {}
            }
        }

        // 等待 async 任务
        for handle in handles {
            if let Ok((idx, result, effects)) = handle.await {
                results[idx] = Some((result, effects));
                executed.insert(idx);
            }
        }
        // 执行 sync 任务
        for (idx, result, effects) in sync_tasks {
            results[idx] = Some((result, effects));
            executed.insert(idx);
        }
    }

    results.into_iter().filter_map(|r| r).collect()
}
```

### 简单问题判断（启发式规则）

```rust
fn should_use_planner(query: &str) -> bool {
    let len = query.chars().count();
    // 太短 → 不需要规划
    if len < 10 { return false; }
    // 包含对比词 → 需要规划
    let compare_words = ["对比", "比较", "区别", "差异", "优劣", "vs", "和", "与"];
    if compare_words.iter().any(|w| query.contains(w)) { return true; }
    // 包含多个实体关键词 → 需要规划
    let entity_indicators = ["项目", "产品", "文件", "笔记", "待办"];
    let entity_count = entity_indicators.iter().filter(|w| query.contains(*w)).count();
    if entity_count >= 2 { return true; }
    // 问题长度 > 50 → 可能需要规划
    if len > 50 { return true; }
    // 默认不需要规划
    false
}
```

### 结果合并

```rust
fn merge_results(results: &[(String, Vec<SessionEffect>)]) -> String {
    let mut merged = String::new();
    let mut seen_chunks = HashSet::new();
    let mut seen_sources = HashSet::new();

    for (result, _) in results {
        for line in result.lines() {
            let tl = line.trim();
            // 去重：按 ChunkID
            if let Some(cid) = tl.strip_prefix("ChunkID：") {
                let short: String = cid.chars().take(8).collect();
                if !seen_chunks.insert(short) { continue; }
            }
            // 去重：按 source_id
            if let Some(sid) = tl.split("source_id: ").nth(1) {
                let sid = sid.trim();
                if !seen_sources.insert(sid.to_string()) { continue; }
            }
            merged.push_str(line);
            merged.push('\n');
        }
        merged.push('\n');
    }
    merged
}
```
