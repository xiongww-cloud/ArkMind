## 二、前端代码审计

### 2.1 KnowledgeBase.vue — 主聊天页面

#### ✅ 优点
1. **流式响应体验佳**：通过 Tauri 事件 `agent:token` 实现实时打字机效果，用户体验流畅
2. **拟人化交互**：冷启动时随机显示思考短句（"让我想想啊……"），工具调用时动态更新状态文案
3. **Markdown 渲染完整**：支持 GFM、表格、代码块、引用等，且经过 DOMPurify 消毒
4. **会话持久化**：通过 `kbSaveSessions`/`kbLoadSessions` 实现 SQLite 持久化，支持多会话切换
5. **工具调用可视化**：`ToolCallCard` 组件清晰展示 ReAct 推理过程

#### ⚠️ 问题与风险

**P0 — 严重**

1. **会话保存时消息删除再重建** (`kb_commands.rs:211`)
   ```rust
   database::run("DELETE FROM chat_messages WHERE session_id=?", &[json!(id)]).ok();
   ```
   每次保存都先 DELETE 再 INSERT，无事务保护。若进程中途崩溃，会话数据将丢失。

2. **XSS 消毒绕过风险** (`sanitize.ts:11-13`)
   ```js
   const PURIFY_CONFIG = { ADD_TAGS: ['input'], ADD_ATTR: ['checked', 'disabled', 'type'] }
   ```
   允许 `<input>` 标签注入，虽然限定了属性，但 DOMPurify 的 `ADD_TAGS` 配置需谨慎，若 AI 返回含 `<input>` 的恶意 HTML 可能被渲染。

3. **Tool result 截断** (`KnowledgeBase.vue:267`)
   ```js
   const TOOL_RESULT_MAX_LENGTH = 30000
   toolResults.push({ content: typeof t.result === 'string' ? t.result.substring(0, TOOL_RESULT_MAX_LENGTH) : '' })
   ```
   30K 字符截断可能导致长工具结果丢失关键信息，且截断后无 `[已截断]` 标记。

**P1 — 高**

4. **消息索引用数组位置** (`KnowledgeBase.vue:395`)
   ```html
   <div v-for="(msg, idx) in currentSession.messages" :key="idx">
   ```
   使用 `idx` 作为 `:key`，当消息顺序变化时 Vue 无法正确复用 DOM 节点。应使用消息唯一 ID。

5. **事件监听器泄漏风险** (`KnowledgeBase.vue:209-241`)
   `listen()` 返回的 `unlisten` 函数在 `finally` 中调用，但如果 `listen` 本身抛出异常（如 Tauri event 系统不可用），`unlistenStream` 可能为 `null` 导致未清理。

6. **会话排序依赖本地时间字符串** (`KnowledgeBase.vue:120`)
   ```js
   sessions.value.sort((a, b) => new Date(b.updatedAt).getTime() - new Date(a.updatedAt).getTime())
   ```
   使用 `toLocaleString('sv-SE')` 格式化的时间字符串跨时区可能解析异常。

**P2 — 中**

7. **打字机效果性能** (`KnowledgeBase.vue:50-57`)
   每 8ms 更新一次 `typewriterText`，触发 Vue 响应式重渲染。长文本（数千字符）会导致高频 re-render，可能造成界面卡顿。建议使用 `requestAnimationFrame` 或批量更新。

8. **重复 Notebook Picker Modal** (`KnowledgeBase.vue:460-517`)
   代码中存在两个几乎完全相同的 `<Teleport to="body">` Notebook Picker Modal（第 460-474 行和第 498-517 行），属于冗余代码。


10. **无消息长度限制** — 用户输入无上限，超长输入可能触发 LLM API 错误或消耗过多 token。

**P3 — 低**

11. **`onMounted` 和 `onActivated` 双重调用** — `onMounted` 加载会话，`onActivated` 再次滚动到底部，在 `keep-alive` 场景下可能导致重复操作。

12. **硬编码的建议提示词** — `suggestions` 数组硬编码在组件中，无法动态配置。

13. **复制功能无 fallback** — `navigator.clipboard.writeText` 在非安全上下文（非 HTTPS/localhost）可能不可用，但无降级方案。

### 2.2 AIAssistantFAB.vue — 浮动助手

#### ✅ 优点
1. **科幻风格 UI 设计**：轨道动画、扫描线、发光效果，视觉体验出色
2. **可拖拽定位**：支持垂直拖拽重新定位 FAB 按钮
3. **独立消息状态**：与主聊天页面独立，不会互相干扰

#### ⚠️ 问题

1. **无会话持久化** — AIAssistantFAB 的消息不持久化，刷新后丢失
2. **无多会话支持** — 只有一个全局对话，无法切换历史会话
3. **`renderMd` 与 `KnowledgeBase.renderMarkdown` 重复** — 两个组件各自实现了几乎相同的 Markdown 渲染函数，违反 DRY 原则
4. **思考动画中的 `setInterval` 泄漏** (`AIAssistantFAB.vue:157`)
   ```js
   const t = setInterval(() => { thinkingProgress.value = full.slice(0, ++idx); if (idx >= full.length) clearInterval(t) }, 30)
   ```
   若组件在动画完成前卸载，`setInterval` 不会被清理
5. **消息 ID 使用 `crypto.randomUUID()`** — 每次渲染生成新 ID，可能在列表重渲染时产生不必要的 DOM 更新

### 2.3 ChatSidebar.vue — 会话侧栏

#### ✅ 优点
- 简洁清晰，支持重命名/删除/新建
- 时间显示人性化（"刚刚"、"X 分钟前"、"昨天"）

#### ⚠️ 问题
1. **无虚拟滚动** — 会话列表无虚拟化，100+ 会话时可能卡顿（当前限制 100 条）
2. **删除无确认** — 虽然父组件有 `confirmDelete` 机制，但侧栏本身没有禁用删除按钮的视觉反馈

### 2.4 ToolCallCard.vue — 工具调用卡片

#### ✅ 优点
- 折叠/展开设计清晰
- 思考过程与工具调用分离展示

#### ⚠️ 问题
1. **`round` prop 无类型定义** — 使用 `any` 类型，缺乏类型安全
2. **结果展示无语法高亮** — 工具结果以纯文本展示，JSON 格式化但无高亮

## 三、后端代码审计

### 3.1 agent_workflow.rs — ReAct Agent 核心

#### ✅ 优点
1. **完整的 ReAct 循环**：支持工具调用、观察、思考的迭代推理
2. **会话记忆系统**：`SessionMemory` 实现了活跃对象追踪、访问计数、焦点管理
3. **多工具支持**：search、object、traverse、todo、memory、learning、policy、project
4. **预算管理**：防止无限循环，有迭代次数限制

#### ⚠️ 问题

1. **硬编码的 system prompt** — `AGENT_SYSTEM_PROMPT` 占用大量代码行，且与前端提示词可能不一致
2. **`SessionMemory` 使用 `Mutex`** — 在异步 Rust 中使用 `Mutex` 可能导致死锁（虽然后端是单线程事件循环）
3. **无消息历史截断** — 长对话的历史消息会持续增长，可能超出 LLM 上下文窗口限制

### 3.2 chat_api.rs — LLM API 客户端

#### ✅ 优点
- 支持 SSE 流式响应
- 配置缓存机制（30 秒 TTL）
- 优雅的配置回退链（ai_config → kb_config → 缓存）

#### ⚠️ 问题
1. **SSE 解析不完整** — `chat_completion_stream` 中 SSE 解析逻辑较简单，不处理多行 `data:` 或 `event:` 类型
2. **无重试机制** — API 调用失败直接返回错误，无指数退避重试
3. **无 token 计数** — 无法预估请求的 token 消耗

### 3.3 kb_commands.rs — Tauri 命令

#### ⚠️ 问题
1. **会话保存无事务** — `kb_save_sessions` 中 DELETE + INSERT 无事务包裹
2. **`kb_load_sessions` 无分页** — 虽有 `LIMIT 100`，但消息数量无上限
3. **SQL 注入风险低** — 使用参数化查询，但部分 LIKE 查询的 `%` 拼接需注意

```

  ↓

  ↓

  ↓
[tauri invoke] → kb_agent_chat — kb_commands.rs:15
  ↓
agent_chat_workflow() — agent_workflow.rs
  ↓ (ReAct loop, max N iterations)
  ├── call_llm_with_tools() → LLM API (tool calling)
  │     ↓
  │   execute_tool() → 各 ext_tool_* 命令
  │     ↓
  │   emit("agent:status/thought/progress")
  │
  └── call_llm_without_tools() → LLM API (streaming)
        ↓
      emit("agent:token") — 实时流式输出
  ↓
kb_agent_chat 返回 result
  ↓
前端显示最终答案 + 打字机效果
```

## 五、安全审计

| 风险项 | 严重度 | 说明 |
|--------|--------|------|
| XSS 消毒 | 中 | DOMPurify 配置允许 `<input>` 标签，AI 输出可能被利用 |
| SQL 注入 | 低 | 使用参数化查询，风险可控 |
| API Key 存储 | 中 | 配置存储在 SQLite `system_config` 表中，使用 `crypto::decrypt_config_api_keys` 解密，需确认密钥管理安全 |
| 会话数据泄露 | 低 | 本地 SQLite 存储，但无加密保护 |
| LLM Prompt 注入 | 中 | 用户输入直接传入 LLM，无输入清洗，可能被利用操纵 Agent 行为 |

## 六、性能审计

| 问题 | 影响 | 建议 |
|------|------|------|
| 无虚拟滚动 | 长对话时 DOM 节点过多 | 引入 `vue-virtual-scroller` 或 `vue-virtuoso` |
| 打字机高频 re-render | 长文本时 UI 卡顿 | 使用 `requestAnimationFrame` 或 chunk 批量更新 |
| Markdown 动态导入 | 每次切换消息时可能重新加载 | 已有缓存机制（`rendered` ref），但首次加载有延迟 |
| 事件监听器管理 | 可能泄漏 | 建议使用 `onUnmounted` 统一清理 |
| 会话保存频率 | 每次发送消息都保存全量会话 | 可考虑增量保存或防抖 |

## 八、总结

整体代码质量**良好**，架构清晰，功能完整。核心的 ReAct Agent 循环设计精巧，流式响应体验流畅。主要问题集中在：

1. **数据持久化可靠性** — 会话保存无事务保护
2. **前端代码重复** — Markdown 渲染、Typewriter 效果在两处重复实现
3. **性能隐患** — 长对话无虚拟滚动，打字机效果高频重渲染
4. **安全细节** — DOMPurify 配置、Prompt 注入防护

建议优先处理 P0 级别的 3 个问题，其余可按迭代逐步改进。
